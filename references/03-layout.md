## 9. 布局与蛇形

一条链占 `ceil(命令数 / W)` 行，每行 `W` 个方块（`W` 默认 **128**）。

❗ **`W` 不是随便定的**：深度 = 方块数 / 宽度，而**深度必须落在区块加载范围内**
（否则链尾那些方块不 tick，表现就是"只有最前面一段命令在跑"）。
16 宽摆 7000 个方块 = 438 行 —— 必挂。128 宽只有 55 行，整块装得下（U36）。

```
init   48 条 → 3 行        z=0..2
                            z=3     空一行隔开
tick  131 条 + 4 闸门 = 135 块 → 9 行   z=4..12
                            z=13    空一行隔开
panel  4 组 19 条 → 4 行   z=14..17
合计 16 × 18，z=16..17 越过区块边界 → 2 个区块
```

❗ **反向行的末块必须沿用本行流向**，不能固定朝东。  
否则它指回前一块，两块互相触发，变成死循环。

按钮放链首正上方（y+1），`stone_button`，`facing_direction=1`（朝上）。

### 9.0 方块自述：让 1000 个方块能被维护（U27 / U31）

一条 100 格射程的枪，命令方块会到 1100 个。**没有自述就没法维护**：
站在世界里只看到一望无际的方块，`Command` 要点开一个看一个。

做法：把说明写进方块实体的 `CustomName`（随 `.mcstructure` 一起走，
`dump_cbworld.py` 会读成 `cb.json` 的 `name`），于是**世界内**和 **JSON 里**都能查。

```
链头（第 0 格）  →  弹道 · 碰撞穷举 → 三段肢体 → 同分 → 受击/碰墙特效 → 粒子
其余格          →  弹道#43 打标      弹道#607 粒子      开火#12 音效
```

- **链头写整条链的概括**：一眼看出这条链负责什么，不用一条条翻。
- **其余格写 `<链名>#<序号> <作用>`**：作用词由命令关键词自动判定
  （`粒子` / `音效` / `HUD` / `置分` / `相机` / `伤害` / `清理`…），**顺序即优先级**。
- 三段式的 `检测` / `连接` / `重置` 必须**显式指定**，不能靠关键词猜
  —— `execute if entity` 这种包装词到处都是，猜出来的全是「检测」。
- 面板链要能拿到自己的 `id`：spec 里存 `{"id":..., "cmds":[...]}`，
  只存 `cmds` 的话自述会退化成「链#07 置分」（A28）。

### 9.1 地板

指令区地板统一 **3 层**（早期版本是 4 层 `bedrock + dirt + dirt + grass`，白占 25% 方块）：

| 层     | 方块                    | 作用                 |
| ----- | --------------------- | ------------------ |
| 底     | `bedrock`             | 兜底，防止挖穿掉虚空         |
| 中     | `black_concrete`      | 衬底                 |
| 面     | `black_concrete`      | 暗底托亮 UI（**默认就用它**） |
| 边缘一圈  | `polished_blackstone` | 粘贴后边界一眼可见          |
| 按钮正下方 | `stone_bricks`        | 一眼看出哪里能按           |


```python
B.make_floor(blocks, w=16, d=16, top=3)   # top = 子区块局部 y 的地板顶面
```

**为什么用深色混凝土**：

1. **暗底托亮 UI**。HUD、菜单都是浅色字，深色地板对比度最高。
2. **不抢颜色**。草方块会被雪盖、被生物踩，绿色还和 UI 的 `§a` 打架。
3. **边界清楚**。边缘一圈深色石，粘贴到复杂地形里一眼能看出指令区的范围。
4. **全版本都认**。这是关键——见下面这条。

❗ **`black_stained_glass` 会显示成「未知方块」**（用户实测：不是空气，是紫黑格子的未知方块）。  
网易服部分版本没注册这个 ID，`structure load` 时不报错，粘出来一片未知方块。  
**默认一律 `black_concrete`**，不要图好看换成黑玻璃。  
自检：`check_props.py` 之前先看 palette 里有没有 `black_stained_glass`。

**实测省下的结构文件体积**：数据化 −3.2%、拔刀剑 −2.0%、断链演示 −6.7%。

## 10. 报错的两套开关

**这是最容易搞混的一处。** 玩家说的"报错"有两种，落在两个不同的地方。

| 你看到的报错                              | 出现在哪              | 谁控制      | 改什么                          |
| ----------------------------------- | ----------------- | -------- | ---------------------------- |
| `Syntax error`、`No targets matched` | **命令方块界面「上一个输出」** | 方块实体 NBT | `TrackOutput` / `LastOutput` |
| 指令反馈、死亡消息、进度提示                      | **聊天栏（灰字）**       | 世界规则     | 6 条 `gamerule`               |

❗ `gamerule commandblockoutput` **只管聊天栏，管不到方块界面**。  
❗ `TrackOutput` **只管方块界面，管不到聊天栏**。两个都要设。

### 10.1 命令方块控制台（改 NBT）

| NBT 键              | 类型           | 作用                |
| ------------------ | ------------ | ----------------- |
| `TrackOutput`      | Byte         | `1` 记录并显示；`0` 不记录 |
| `LastOutput`       | String       | 上一次输出的文本（报错原文）    |
| `LastOutputParams` | List<String> | 输出分段参数            |

交付版：

```
TrackOutput = 1
LastOutput = ""          ← 出厂留空，跑起来自然写入
LastOutputParams = []
```

**为什么保留 1**：命令方块系统出问题，九成靠"点开那个方块看上一次输出"定位。  
关掉 `TrackOutput` 等于把唯一的内置日志删了——玩家报"不生效"，你只能靠猜。  
代价只是每个方块多几十字节，结构文件大几 KB，完全不值得省。

**真要静音**：只有一种情况——方块摆在玩家能点到的公共区域，怕他们看到红字误会。  
那时才设 `TrackOutput=0`，但必须同时留一份 `debug_output: true` 的调试版世界。

**两套开关的正确组合**：

| 目的       | `TrackOutput` | 6 条 gamerule   |
| -------- | ------------- | -------------- |
| **交付默认** | **1（保留）**     | 全 false（聊天栏干净） |
| 玩家能点到方块  | 0             | 全 false        |
| 自己调试     | 1             | 全 true（连反馈一起看） |

### 10.2 聊天栏灰字（改 gamerule）

```
gamerule sendcommandfeedback false     ← 必须第一条，它一关后面都不回显
gamerule commandblockoutput false
gamerule showdeathmessages false
gamerule announceadvancements false
gamerule showrecipemessages false
gamerule showcoordinates false
```

❗ **顺序陷阱**：`sendcommandfeedback` 一旦关掉，后面这些 `gamerule` 命令自己的回显也没了。  
所以它必须排在最前面。

**管不了的部分**：玩家加入/离开提示在基岩版没有对应 gamerule，  
只能靠服务器插件或资源包。纯命令方块做不到。

**副作用**：关掉后玩家自己打错指令也看不到提示。这是有意的——  
正式地图里玩家不该看到任何系统提示。

### 10.3 报错怎么读

| 报错                   | 含义       | 修法                            |
| -------------------- | -------- | ----------------------------- |
| `Syntax error`       | 语法/参数顺序错 | 对 `execute` 子句顺序              |
| `No targets matched` | 选择器没命中   | 检查 `scores` / `hasitem` / `r` |
| `Unknown command`    | 该版本没这条指令 | 换老写法                          |
| 什么都不显示               | 命令方块没被激活 | 检查 `auto` 与红石                 |

## 74. 常加载区块 `tickingarea` ★ 交付必做

**指令区不在玩家附近，不加常加载区块就一条都不跑。** 真实地图全部有这一步：

```mcfunction
tickingarea add 100000 0 100000 100063 0 100063 指令        # 矩形
tickingarea add circle 552 0 1048 4 关卡                    # 圆形（半径 4 区块）
tickingarea remove vladi_hub                                # 先删再建，防重复
```

弗拉迪的完整写法（先删后建，保证幂等）：

```mcfunction
tickingarea remove vladi_hub
tickingarea remove vladi_c
tickingarea add ~-2 ~-2 ~-2 ~65 ~30 ~6 vladi_hub true
tickingarea add circle ~30 ~ ~2 4 vladi_c true
```

- 名字随便起，但**必须唯一**，否则 `remove` 删不干净
- 末尾 `true` = 预加载（世界一开就加载，不等玩家走近）
- **一个世界最多 10 个常加载区**

> **交付检查项**：指令区坐标离出生点 > 4 区块时，`tickingarea add` 必须写进初始化链。

## 64. 六张图的家底

| 图          | 方块   | 循环块 | 其中 `auto=1` | 脉冲块 | 条件块 | 主朝向   | 链长中位 |
| ---------- | ---- | --- | ----------- | --- | --- | ----- | ---- |
| GKM 指令区    | 799  | 56  | **37**      | 18  | 26  | 北 / 东 | 3    |
| 弗拉迪尾刺      | 164  | 2   | **1**       | 1   | 0   | 东 / 西 | 25   |
| 指令区 2      | 625  | 48  | **45**      | 17  | 0   | 东     | 2    |
| 指令区 −10000 | 1777 | 70  | **55**      | 21  | 0   | **上** | 5    |
| 指令区 999    | 2712 | 229 | **10**      | 38  | 0   | 南 / 北 | 2    |
| 虚数指令       | 3050 | 137 | **118**     | 22  | 0   | 东 / 西 | 4    |

**三条结论，直接改认知：**

1. **条件块几乎没人用**：26 / 9127 = **0.3%**，且集中在一张图里，用法是"上一条成功才跟一条"，  
   而且每条都自带完整条件——**从不靠级联传递**。本 skill 禁用它，站得住。
2. **循环块 ≠ 开销**：指令区 999 有 229 个循环块，但只有 **10 个 `auto=1`**。  
   剩下 219 个是 `auto=0`，等红石/按钮激活。**真实开销只看 `auto=1` 的那批。**
3. **单长链是主流**：弗拉迪 164 块里只有 1 条链在跑，长度 135 块。  
   代价是**每刻顺序跑满 135 条**（只是选择器不匹配就秒过）。  
   本 skill 的"多链闸门"方案能把空闲压到 3–4 条——这是**我们比真实地图省**的地方，别被带跑。

## 65. 三种真实布局

### 65.1 横排蛇形（最常见，GKM / 指令区 2 / 虚数）

行与行之间**空一行走线**，链在行末拐弯：

```
z=0  ①②③ … ⑳                       → 东
z=1  （空行，只有初始化按钮/红石走线）
z=2  ㉑㉒ …                          → 东
z=3  ← … ㊵                          → 西（回程）
```

弗拉迪实测：`z=0` 初始化 24 块、`z=2` 主循环 64 块、`z=3` 回程 64 块，**`z=1` 全程空着**。  
空行不是浪费——按钮、红石、走线全在那一层，检修时一眼看清。

### 65.2 竖直塔（省地皮，指令区 −10000）

**1362 个方块朝上（`facing_direction=1`）**，最长一条 **367 块**竖着堆。

```
y=-51  setblock ~~-1~ air []
y=-50  execute as @e[type=fishing_hook] …
y=-49  execute as @e[tag=开火] …
  ⋮            （一路向上 367 格）
y=316  …
```

占地只有 **1×1**，代价是得飞上去改。适合"一次成型、不常改"的成品区。  
**竖直链的朝向只有两个数字：`1` = 向上（运行方向）、`0` = 向下（链首方向）。**


### 65.3 短链网格（每事件一链，指令区 999）

267 个链首，链长中位 **2**——大量"2 块一组"的小链：

```
[0] rep    execute as @a[tag=购买] run setblock ~~~1 chain_command_block 3
[1] ch     <业务>
```

**这就是本 skill 的骨架在真实地图里的样子**：一个事件一条短链，用 `setblock` 改朝向断掉。  
缺点是链多（空闲条数 = 链数），优点是不互相牵连。
