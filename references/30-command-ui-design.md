# Minecraft 基岩版命令 UI 设计 Skill

## 摘要

**这是什么**：一套只用原版命令实现的游戏内 UI 设计方法。所有设计均提炼自用户提供的命令集合，包含 24 种可直接套用的版式、一套统一的配色与符号规范，以及实现动态效果的核心机制。

**能做什么**：聊天栏的资源/价格/公告卡片；动作栏的多级菜单与拨号盘；头胸腿血量、武器弹药、BOSS 血条等 HUD；进度条与菜单开启动画；流光装饰线、像素画、状态侧栏面板；进入地点的标题。

**核心方法**：

1. **选通道**：一次性信息用聊天栏，常驻界面用动作栏，血条与进度用副标题，进入地点用标题。
2. **选版式**：从 §5 版式库挑最接近的一种，不要凭空发明新风格。
3. **套规范**：颜色按 §2.1，符号按 §2.2，同一子系统用同一主题色。
4. **接机制**：选中高亮、状态切换、分档条、动画，全部用 §4 的 `translate` 机制实现。
5. **做检查**：输出前对照 §7 的清单。

**怎么读**：写命令前先读 §1–§4；找具体界面直接查 §5 的版式编号；赶时间看 §6 的模板。

## 1. 基础

### 1.1 输出通道

| 通道 | 命令 | 适合 | 特点 |
|---|---|---|---|
| 聊天栏 | `tellraw` | 奖励、价格、公告、申请、错误 | 留在聊天记录，可多行 |
| 动作栏 | `titleraw … actionbar` | 菜单、HUD、区域名、交互提示 | 必须每 tick 刷新，可用 `\n` 多行 |
| 标题 | `title` | 进入地点的大标题 | 居中大字 |
| 副标题 | `title … subtitle` / `titleraw … subtitle` | BOSS 血条、治疗进度、像素画 | 可单独刷新，用大量 `\n` 调整位置 |

选择原则：看完即走的信息用聊天栏；需要随状态变化的界面用动作栏；动作栏被菜单占用时，血条类内容放副标题。

### 1.2 语法骨架

```mcfunction
# 聊天栏：文字 + 分数
execute as @a[scores={价格=0..}] at @s run tellraw @s {"rawtext":[
  {"text":"\n §lGhopping >§r§f商品价格\n"},
  {"text":"§f§e Price §f> 货物价格§f. "},{"score":{"name":"@s","objective":"价格"}}
]}

# 动作栏：每 tick 执行
execute as @a[scores={菜单=1..}] at @s run titleraw @s actionbar {"rawtext":[
  {"text":"§p▏§7 * §d菜单 §7*§r menu §r>>> information"}
]}

# 标题：纯文本写法
execute as @p[tag=机关] at @s run title @s title §g◁§7།§f 交易市场 §7།§g▷
```

写作规则：

- 复杂界面一律用 `rawtext` 数组，把文字、`score`、`selector`、`translate` 拆成独立片段。
- 分数片段：`{"score":{"name":"@s","objective":"计分项"}}`；`name` 也可以是虚拟玩家，如 `"折扣"`。
- 实体片段：`{"selector":"@s"}` 输出玩家名；`{"selector":"@r[r=2,c=1,type=item]"}` 输出掉落物名，可用于“称号”“已装备物品”。
- 换行用 `\n`；块字符可写成 Unicode 转义（如 `▔`）以避免编码问题。
- 每个片段末尾用 `§r` 重置样式，防止串色。
- 每个界面用计分板状态限定可见对象，例如 `execute as @a[scores={…}] at @s run`。

### 2.2 符号库

| 用途 | 字符 |
|---|---|
| 括号 | `◁ ▷ ◀ ▶ 〖 〗 【 】 『 』 ｛ ｝ 《 》 〈 〉 ［ ］ ◢ ◣` |
| 竖条 | `▏ ▎ ▍ ▌ ▋ ▊ ▕ │ ┆ ┃ ║ ╢ ╟ ‖` |
| 横线 | `▔ ▁ ━ ─ ▰ -` |
| 进度与块 | `█ ▍ ▃ ▆ ࡆ` |
| 指示 | `➤ ◇ ◈ ◆ ▶ ❖ > >>>` |
| 装饰 | `☾ ☫ ☽ ۞ ∬ ☬ ☉ ◥ ◤ ╱ ╲ ﹎ ￣` |
| 全角字母 | `Ｓｔａｒｔ　Ｇａｍｅ`（字母、数字、空格都用全角，适合大标题） |
| 间隔字 | `雪 球 菜 单`、`m e n u`（字间加空格，制造科技感） |

使用约束：

- 同一界面只用一种括号体系和一种竖条体系。
- 全角字符占两格宽，与半角混排时需要补空格对齐。
- 块字符宽度随设备字体略有差异，务必在目标设备上测试。

### 2.3 排版规则

1. **三段式**：标题行 → 内容区 → 提示行。
2. **分隔线**：竖条菜单用 `§7` 的连字符 `-`（50–75 个）；箭头菜单用 20 个 `▔`。
3. **选项行**：每行放 3 项左右，选中项变色。
4. **字段行**：`§<色>▎ §i字段名 §f值`。
5. **双语标签**：中文主标签，后接灰色英文副标（如 `Price > 货物价格`）。
6. **留白**：用 `\n` 空行分段；动作栏顶部加 `\n` 可抬高位置，不遮挡视野中央。
7. **行宽**：单行不超过约 30 个全角字符，超出就换行。
8. **操作提示**：每个界面末尾写清怎么操作（抬头、低头、丢出、下蹲等）。

### 2.4 文案约定

- **英文前缀**：`Weather >`、`Clean up >`、`Propre >`、`Ghopping >`、`Equipment`、`Danger hint`、`Regional information`、`Condition >`、`Reloading...`。
- **双语对照**：`Price / 货物价格`、`Discount / 今日折扣`、`Retrieve / 回收价格`、`Team-up system / 组队系统`、`information / 信息`。
- **品牌签名**：`Next：Generation.勇者之城`、`辣条生存服`、`遥遥领先`。
- **语气**：玩家称“小勇者”，说明保持直白。

## 3. 交互模型

| 概念 | 做法 |
|---|---|
| 选中项 | 用计分板值表示，如 `雪球菜单=1..6`、`menu=1..2` |
| 多级菜单 | 用数值区间分层：`menu=1..2` 为一级，`menu=21..35` 为二级；同一视觉可复用到不同区间（`雪球菜单=1..6` 与 `181..186`） |
| 确认 / 返回 | 抬头 `rx=-88`、低头 `rxm=88`、丢出物品、下蹲、手持附魔瓶 |
| 与 HUD 互斥 | HUD 命令加 `unless score @s menu matches 1..`，菜单打开时 HUD 让位 |
| 唯一可见界面 | 各界面的条件区间不重叠 |
| 计时 | 用计数器计分项（`dh`、`计算`、`换弹`）驱动动画和定时显示 |

## 4. 动态机制（必读）

### 4.1 条件显示：`%%2`

基岩版规则：`with` 中的 `selector` 没有匹配到实体时，该参数会被丢弃，参数列表随之变短；`%%N` 取的是丢弃之后的第 N 个参数。

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={菜单=1}]"},
  {"text":"§d"}
]}}
```

- 条件成立：列表为 [选择器结果, 文本]，`%%2` 取到文本，于是显示。
- 条件不成立：选择器被丢弃，列表只剩 [文本]，`%%2` 不存在，于是什么都不显示。

用途：选中高亮（输出颜色码）、状态标签（输出文字）、条件数值（第二个参数放 `score`）。

选项的标准写法，顺序不能错：**默认色 → 条件染色块 → 选项文字**。

```json
{"text":"§7"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={雪球菜单=1}]"},{"text":"§d"}]}},
{"text":"# 传送主城 "}
```

### 4.2 分档选择：`%%9`

用于血条、弹药条、区域名、动画帧。写法：`with` 里先放 **8 个累进条件选择器**，再放 **8 个候选文本**，译文串写 `%%9`。

原理：设成立的选择器数为 k，则列表长度为 k + 8，`%%9` 取第 9 个，也就是第 (9 − k) 个候选文本。选择器写成累进区间，数值越大成立的越少，选到的文本越靠后：

```
hp=1..10   → k=8 → 文本 1
hp=11..20  → k=7 → 文本 2
…
hp=61..70  → k=2 → 文本 7
hp>70      → k=1 → 文本 8（放下一级嵌套）
```

规则：

- 选择器：`{x=1..10}`、`{x=1..20}`、…，上限递增，最后一个用兜底上限。
- 候选文本从最低档排到最高档。
- 区域名：选择器写 `地区=..0 … 地区=..7`（只写上限），0 对应文本 1，7 对应文本 8。
- 动画帧：选择器写 `dh=27..27 … 27..34`，dh=27 对应帧 1，dh=34 对应帧 8。

### 4.3 多级嵌套（超过 8 档）

把第 8 个候选文本换成下一级 `translate`：

```
%%9（8 选择器，文本 1–7，[ %%9（8 选择器，文本 1–7，[ %%7（6 选择器，文本 1–6）]）]）
```

- 第 1 级覆盖 1–70，第 2 级覆盖 71–140，第 3 级覆盖 141–200。
- 第 3 级只有 6 个选择器，所以译文串写 `%%7`（6 个选择器 + 第 1 个文本 = 第 7 位）。
- 译文串中的数字永远等于“选择器个数 + 1”。

### 4.4 计数器动画：`%%1…%%8`

译文串里直接写 `%%1 … %%8`，`with` 放 8 个条件 `translate`：第 n 个在 `dh=n` 时输出亮色码，否则输出空。`dh` 每 tick 加 1，亮点逐格移动，形成流光。多层菜单可用 `dh`、`dh1` 等独立计数器分别驱动。

### A. 聊天栏提示

#### A1 资源变动卡

适用：经验、金币、灰烬、钻石、碎片、等级的增减提示。

```mcfunction
execute as @a[scores={金币奖励=1..},c=1] at @s run tellraw @s {"rawtext":[
  {"text":"§f｜§g〖§e金币 §f> "},{"score":{"name":"@s","objective":"金币"}},
  {"text":" + "},{"score":{"name":"@s","objective":"金币奖励"}},
  {"text":"\n §eGold coin ：§f "},{"score":{"name":"金币前置","objective":"计算"}}
]}
```

结构：

```
｜〖<中文名> > <当前值> + <增量>
 <English> ： <前置值>
```

- 第一行：白色 `｜`、框色 `〖`、名色中文名、当前值、增量。
- 第二行：名色英文名与白色前置值（前置值来自 `计算` 虚拟玩家）。
- `奖励=1..` 触发，`c=1` 保证只结算一次，展示后应把奖励分数清零。
- 六种资源只需换颜色和名称，经验的当前值用 `xp`，等级用 `experience`。

#### A2 价格卡

适用：商店商品价格、今日折扣、回收汇率。

```mcfunction
execute as @a[scores={价格=0..}] at @s run tellraw @s {"rawtext":[
  {"text":"\n §lGhopping >§r§f商品价格\n"},
  {"text":"§f§e Price §f> 货物价格§f. "},{"score":{"name":"@s","objective":"价格"}},
  {"text":"\n §dDiscount§f ｜ 今日折扣 ｜ §7< §f"},
  {"score":{"name":"折扣","objective":"计算"}},{"text":"§7 >§f"}
]}

execute as @a[scores={回收=0..}] at @s run tellraw @s {"rawtext":[
  {"text":" §l今日>§r§f回收汇率： 1.0/0."},{"score":{"name":"折扣","objective":"计算"}},
  {"text":"\n§g Retrieve §l§f> 回收价格§r§f： "},{"score":{"name":"@s","objective":"回收"}}
]}
```

要点：开头空一行，与聊天流隔开；店名前缀粗体；每行“英文标签 + 中文标签”；折扣数值用灰色尖括号弱化。

#### A3 系统公告

格式：`§l<英文前缀> >§r §f<内容>`，强调数字用 `§7`，多行时第二行补充动作建议。

```mcfunction
tellraw @a {"rawtext":[{"text":"§lWeather >§r§f天气变动 "}]}
tellraw @a[scores={uid=0..}] {"rawtext":[{"text":"§7"},{"text":"§d折扣刷新§f > §r§f即将刷新商品折扣 §7"}]}
tellraw @a[scores={uid=0..}] {"rawtext":[{"text":"§7"},{"text":"§l§fPropre > §r§f共清理 §7"},{"score":{"name":"item","objective":"数量"}},{"text":"§f 无用物品"}]}
tellraw @a[scores={uid=0..}] {"rawtext":[{"text":"§lClean up >§r .5s§7即将清理掉落物\n请各位小勇者保管好§f： 战利品"}]}
```

`scores={uid=0..}` 让公告只发给已注册玩家。

#### A4 加入广播

格式：`>> UID:<编号> <玩家名> <当前人数>/<上限> 加入 <服务器品牌>`。

```mcfunction
execute as @a[scores={上线=0,uid=1..}] at @s run tellraw @a[tag=!屏蔽] {"rawtext":[
  {"text":">§7>§f UID:"},{"score":{"name":"@a[scores={上线=0,uid=1..}]","objective":"uid"}},
  {"text":" "},{"selector":"@s"},{"text":"§f "},
  {"score":{"name":"总人数","objective":"数量"}},{"text":"/10 加入§fNext：Generation.勇者之城"}
]}
```

`>` 用 `§f` 与 `§7` 叠成双箭头；`tag=!屏蔽` 让玩家可以关闭广播。

带称号的两行版本，第二行箭头比第一行淡（`§b` → `§7`），形成层级：

```mcfunction
execute as @e[name=ch] at @s run tellraw @a[tag=!屏蔽] {"rawtext":[
  {"text":"§f>§b> §f称号:"},{"selector":"@r[r=2,c=1,name=!木桶,type=item]"},
  {"text":"\n§f>§7>§f "},{"selector":"@a[scores={上线=0}]"},{"text":"§f "},
  {"score":{"name":"总人数","objective":"数量"}},{"text":"/10 加入§fNext：Generation.勇者之城"}
]}
```

#### A5 装备清单

```mcfunction
execute as @e[name=装备,type=armor_stand] at @s run tellraw @p[tag=装备] {"rawtext":[
  {"text":"§a< §fEquipment§a > §f已装备物品: "},
```

#### A6 申请通知卡

### E. 装饰与面板

#### E1 流光装饰线

用计数器 `dh` 让某一格“亮起”，每 tick 后移一格，形成扫描光。

**8 格横幅（`-{LA SMP}-`）**

```
 §2§o ▏▏▏§a│ ─ §b─ -{§aL§qA §eS§gM§6P§b}-─ §a─ │‖§2
 §o  ▏▏▏%%1▏§2%%2▏▏§2%%3▏▏▏§2%%4▏▏▏▏§2%%5▏▏▏▏▏▏▏§2%%6▏▏▏▏▏▏▏▏▏§2%%7▏▏▏▏▏▏▏▏▏▏▏§2%%8▏▏▏▏▏▏▏▏▏
```

- 译文串里的 `%%1…%%8` 对应 `with` 里的 8 个条件 `translate`，`dh=35…42` 时第 n 个输出 `§a`。
- 底色 `§2` 深绿，亮起段 `§a` 亮绿。
- `▏` 数量逐段递增（1、1、2、3、4、7、9、11、9），光带呈渐宽的透视感。

## 7. 检查清单与常见问题

### 7.1 输出前检查

- [ ] 通道选对：一次性用聊天栏，常驻用动作栏，血条与进度用副标题，进入地点用标题。
- [ ] 同一子系统的标题括号、分隔线、竖条同色；资源颜色与 §2.1 一致。
- [ ] 条件块成对出现，互斥分支不会同时显示。
- [ ] `%%9` 的选择器与候选文本数量匹配，区间累进，译文串里的数字等于选择器数加 1。
- [ ] 菜单每一项都有选中与未选两态，选项前先写默认色再插条件染色块。
- [ ] 菜单有操作提示和关闭提示。
- [ ] HUD 与菜单互斥，动作栏命令每 tick 执行。
- [ ] 全角字符已对齐，块字符在目标设备上测试过。
- [ ] 没有残留的调试条件（如 `name=tm`）。
- [ ] 聊天类提示结算后已清零奖励分数，避免重复刷屏。

### 7.2 常见问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 动作栏一闪而过 | 没有每 tick 刷新 | 放进循环命令方块或 `tick.json` |
| 颜色串色 | 缺少 `§r` 或默认色 | 片段末尾补 `§r`，选项前先写 `§7` |
| 条件文本不出现 | 选择器没命中 | 用 `/testfor @s[scores={…}]` 单独验证 |
| 选中色一直亮着 | 条件块写在默认色之前 | 顺序改为：默认色 → 条件染色 → 文字 |
| `%%9` 档位错位 | 选择器与文本数量对不上，或区间不累进 | 8 个选择器配 8 个文本，上限递增，最后用兜底上限 |
| 血条对不齐 | 每档字符总数不同 | 统一总格数，空段用 `§8` 补足 |
| 多个界面叠在一起 | 状态区间重叠 | 重新规划数值区间（见 §3） |
| 字符显示为方框 | 设备字体缺字 | 换通用块字符，并在目标设备测试 |
| 动画卡在某一帧 | `dh` 没有递增或没有复位 | 每 tick 加 1，到上限后清零 |

## 结语

命令 UI 的难处不在某一条命令，而在整体的一致性：玩家看到的是一套界面语言，而不是一堆零散的提示。本 skill 反复在做三件事：

- **统一**：同类资源固定同色，同一子系统固定一套主题色、括号和分隔线，让玩家不用读字就能分辨来源。
- **分层**：聊天栏承载一次性信息，动作栏承载常驻界面，副标题承载血条与进度；菜单用数值区间分层，HUD 在菜单打开时让位。
- **留余地**：每个界面都写明操作方式与关闭路径，并给英文副标和品牌签名留出位置。

实际制作时，建议先在 §5 找到最接近的版式，复制后只改计分项、文案和颜色，再对照 §7 检查。`%%2`、`%%9` 的行为取决于游戏版本，上线前请先在目标版本里实测一遍。
