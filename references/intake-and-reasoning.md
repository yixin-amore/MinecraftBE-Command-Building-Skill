# 提问、期待效果与联想创新

> 目标：让 AI 先问对问题、把“想要的感觉”翻译成设计杠杆，再用联想/发散/收敛做出新东西。  
> 不是审问用户，也不是让用户写需求文档。

## 1. 什么时候问

| 请求 | 做法 |
|---|---|
| “这条命令怎么写 / 为什么报错” | 直接答，不问设计问题 |
| “设计一个系统 / 地图 / Boss / 菜单” | 先做 3–7 个高杠杆问题 |
| “随便 / 你看着办” | 给默认方案 + 3 个方向，明确假设 |
| 用户已给坐标/尺寸/参考/输出 | 不重复问，只问缺口 |
| 需求模糊但可先做 MVP | 先做最小闭环，再问扩展 |

**先读已有文件/上下文**；能从文件推断的，不要问用户。

## 2. 提问顺序（3 轮，最多 7 个）

### 第 1 轮：期待效果（最重要）

1. **玩家第一眼/前 30 秒要看到或感受到什么？**
   - 震撼 / 紧张 / 爽 / 神秘 / 仪式感 / 幽默 / 压迫 / 治愈
2. **玩家主要做什么？**
   - 战斗 / 解谜 / 探索 / 建造 / 经营 / 社交 / 竞速
3. **成功和失败分别长什么样？**
   - 一句话描述“通关瞬间”和“团灭瞬间”

### 第 2 轮：约束

4. **坐标/尺寸/单人还是多人/目标版本？**
5. **必须复用或不能动什么？**
   - 现有建筑、菜单、经济、Boss、领地、UI、世界观
6. **输出要什么？**
   - 设计 / spec / 命令 / BDX / 建筑体块 / 预览图

### 第 3 轮：差异点

7. **最不想像什么？哪个参考作品/关键词最接近？**

问完后**复述**：

```text
我理解的目标：
期待效果：
硬约束：
未知/假设：
```

不要一次问 15 个问题；不要问“你想要什么风格”这种没有选项的空问题。

## 3. 把“期待效果”翻译成设计杠杆

| 用户说 | 设计杠杆 |
|---|---|
| 震撼 | 尺度、剪影、对比、光源、声音、开场揭示 |
| 紧张 | 倒计时、前摇、窄安全区、递增音效、镜头抖动 |
| 爽 | 命中反馈、连击计数、粒子/音效、击退、阶段突破 |
| 神秘 | 遮挡、低照度、碎片叙事、未知地图、远处光点 |
| 仪式感 | 空间序列、门/阶梯/祭坛、音乐、标题、灯光渐亮 |
| 压迫 | 高尺度、低机位、Boss 注视、环境收窄、阴影 |
| 社交 | 共享状态、分工、排行榜、观战、组队门槛 |
| 探索 | 地标、环路、视线引导、奖励密度、隐藏路径 |

**形容词不是需求**；“震撼”要落到尺度/光/声音/空间中的一个主焦点。

## 4. 联想：把两个系统咬合

8 层联动矩阵：

```text
触发 → 状态 → 数据 → 表现 → 空间 → 成长 → 社交 → 保护
```

每次设计至少找 **2 条跨层连接**：

- 触发 → 数据：雪球 → 菜单页 → 个人面板
- 数据 → 空间：护盾破裂 → 场地塌陷
- 空间 → 表现：进入祭坛 → 灯光/音乐/标题
- 成长 → 社交：排行榜 → 组队门槛 → 商店

**跨域类比**：

| 领域 | 借用 |
|---|---|
| 音游 | 节拍、判定窗、连击 |
| 塔防 | 波次、路径、资源 |
| 卡牌 | 冷却、抽牌/随机池、组合 |
| 生存 | 资源、饥饿/温度、风险回报 |
| 电影 | 开场/铺垫/高潮/反转 |
| 建筑 | 轴线、框景、序列、光影 |
| 桌游 | 回合、角色、投票、合作 |

## 5. 创新：约束内产生新连接

### 5.1 SCAMPER

- **替代**：把按钮换成钓鱼钩/雪球/触摸点
- **组合**：Boss 护盾 + 场地塌陷 + 音乐阶段
- **借用**：音游判定 → 技能前摇
- **修改**：把“打 Boss”改成“保护 Boss”
- **放大/缩小**：一个区块内做完整副本
- **重排**：先结算再演出，或先演出再结算
- **反转**：Boss 越打越弱？玩家必须不打？

### 5.2 约束法

- 只用一个命令方块
- 只用一个区块
- 不用 `camera`/行为包
- 不用 UI，只靠空间/声音
- 100 个方块内做出记忆点

### 5.3 视角法

- 从 Boss 视角看玩家
- 从建筑/雕像视角看战斗
- 从 UI/数据视角看世界
- 从失败者视角重演

### 5.4 组合法

从两个不相关系统各取一个机制，强制连接：

```text
雪球菜单 × 塔防 = 用菜单布置防御波次
FMBE × 音游 = 按节拍触发模型阶段
建筑 × 卡牌 = 房间即卡组，进入房间抽效果
```

## 6. 思考协议（内部分步）

```text
1. Recon：读文件/上下文/现有系统
2. Frame：目标、期待效果、约束、成功标准
3. Model：状态机/数据流/队列/树/图/数学
4. Associate：8 层联动 + 跨域类比
5. Diverge：稳健/联动/大胆 3 方向
6. Evaluate：新鲜感/一致性/可落地/性能/可读性/可测试
7. Red-team：多人/性能/逃课/误判/重置/版本
8. Freeze：冻结 spec，再写命令
```

输出时只给**结论和理由**，不需要把内部思维链全部倒给用户。

## 7. 回答模板

```text
1. 我理解的目标 / 期待效果 / 硬约束
2. 3 个方向（稳健 / 联动 / 大胆）
3. 推荐 + 理由
4. 联动图 + 最小闭环
5. 还需要你确认的 1–3 个点
```

如果用户说“直接做”，跳过提问，但在开头写：

```text
假设：坐标/尺寸/多人/性能按以下默认...
```

## 8. 反模式

- 一上来写 200 条命令，再问“这样可以吗”
- 问 20 个问题，用户失去耐心
- 只问“什么风格”，不给选项/默认
- 把“震撼”当成“加更多粒子”
- 只做一个系统，不和现有内容联动
- 第一个念头就开工，不做 3 方向
- 不写假设，最后返工
