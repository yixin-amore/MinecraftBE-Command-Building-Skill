# 建筑/指令语料：理解、归类、模仿、建造

> 语料：Sunrain 文件包 V2.8（4,583 个文件，1,868 MB）
> 组成：2,370 个 `.schematic`、30 个 `.schem`、265 个 `.bdx`、1,915 张参考图。
> 实测：classic 2,182 / Sponge 172 / 缺尺寸 45 / unknown 1；有配对图 906。
> 目标：不是把 1.8 GB 塞进上下文，而是建立**可检索的索引 + 风格卡 + 建造流程**。

## 1. 语料不是“一个文件夹”，是四种资产

| 类型 | 作用 | 处理 |
|---|---|---|
| `.schematic` / `.schem` | 建筑体块、材质、尺寸 | 读 NBT：W/H/L、Palette/Blocks、TileEntities |
| `.bdx` | 命令方块系统 | 读命令：数量、类型、前缀、关键词 |
| 图片 | 外观/风格/配色/构图 | 与同名结构配对，做视觉检索 |
| 目录名 | 作者分类 | 建筑/主城/Lobby/空岛/起床/音乐/像素画/更新 |

**不要只看扩展名**：语料里混有 classic MCEdit、Sponge v2、带命令块 NBT 的脏文件、重复文件、空文件。

## 2. 先建索引，不要先“读全部”

技能脚本：

```bash
python3 scripts/sunrain_index.py "/path/to/文件收集V2.8" out/
```

输出：

- `index.jsonl`：每个文件的路径、大小、分类、标签、尺寸、Palette、BDX 统计、配对图。
- `stats.json`：总量、扩展名、分类、格式、标签、体积。
- `catalog.md`：按类别的高价值样板。
- `contact-sheet.jpg`：Top 40 参考图拼图。

查询：

```bash
python3 scripts/corpus_query.py out/index.jsonl --category architecture --tag style:中式 --limit 10
python3 scripts/corpus_query.py out/index.jsonl --min-width 100 --paired --limit 20
python3 scripts/schematic_blocks.py "某建筑.schematic"
```

## 3. 归类：三层标签

### 3.1 功能

### 3.2 风格

### 3.3 元素

三层组合就是检索语句：

> “中式 + 主城 + 雪山 + 100×60×100 以内 + 有参考图”

## 4. 质量信号（排序用）

- 目录：`珍品`、`高质量`、`建筑系列[全]`、`归寻`、`服务器`。
- 有配对图：能看外观，优先。
- 尺寸/体积：太小是部件，太大是整图；按目标规模选。
- 文件大小：异常小可能是空壳/脏文件。
- BDX 命令数：命令系统复杂度。
- 名称：`推荐`、`正式版`、`全`、`私货`。

## 5. 从参考到风格卡

对每个候选，抽 1 页风格卡：

```
名称/路径：
类型：主城/大厅/空岛/...
尺寸：W×H×L；体积
轮廓：主塔/屋顶/入口
材质：Palette Top 10（主/次/强调）
层高：基座/墙身/檐口/屋顶
细节密度：每 10×10 立面装饰块
动线：入口→核心→出口
可借鉴：3 条
不照搬：2 条
```

用 `schematic_blocks.py` 得到 Palette 百分比；用配对图看轮廓/配色。

## 6. 模仿：改变约束，不复制坐标

至少改 3 项：

- 场地（平地→山地/海岛）
- 功能（主城→副本入口）
- 尺度（×0.7 / ×1.5）
- 文化母题（中式→日式/幻想）
- 材质家族（石→深板岩/铜）
- 动线（直线→环形/多层）

保留：

- 体量主次
- 屋顶出檐/收分
- 材质 60/30/10
- 入口识别
- 细节密度节奏

## 7. 建造：先体块，后装饰

1. 场地/轴线
2. 主/次/附体块
3. 屋顶/轮廓
4. 立面开洞/柱/檐
5. 材质分带
6. 内部空壳/楼梯
7. 内饰/灯光
8. 环境/植被/道路
9. 截图校准（正面/侧面/俯视）
10. 导出：`.schematic` / `.bdx` / `.mcworld`

## 8. BDX 语料怎么学

不要逐条读 265 个 BDX；先聚合：

- 每个文件的命令数、repeat/chain/impulse、conditional、delay。
- 命令前缀 Top（execute/scoreboard/summon/playanimation/particle/...）。
- 关键词：菜单、商店、Boss、FMBE、技能、阶段、抽奖、领地、反作弊。
- 选 3 个代表：最小可用、最复杂、最独特。

然后把模式写进技能：

- 菜单 → 页面/按钮/返回
- 商店 → 价格/库存/扣款/发货
- Boss → 阶段/技能/血条/死亡
- FMBE → 部件/动画/性能

## 9. 语料的坑

- **格式混杂**：classic MCEdit（Blocks 数字 ID） vs Sponge（Palette/BlockData）；同一扩展名不代表同一格式。
- **脏 NBT**：有些文件根部混入命令方块/箱子/告示牌字段；不要假设所有键都属于建筑。
- **空壳/损坏**：`Blocks` 长度为 0、`f8/文件无效`；索引时标记 `unknown`。
- **重复**：同名 `(1)`、不同版本目录；先按名称/尺寸去重，不要重复学习。
- **图片与结构不同名**：配对失败时用目录/相邻文件人工确认。
- **版权**：参考可以学规律，不要 1:1 复制他人地图；交付时注明参考与改动。

## 10. 推荐工作流（AI）

```
用户要“中式主城”
  → 检索 index：category=architecture, style:中式, paired
  → 取 3 个不同尺度参考
  → 生成风格卡（Palette/体量/屋顶/细节）
  → 写 building brief（新场地/新功能/新动线）
  → 先体块/屋顶，截图校准
  → 再加立面/内饰/环境
  → 导出 BDX/MCWorld
```

这样 AI 学到的是**可迁移规律**，不是 1.8 GB 的记忆。
