# 值噪声 / 精度哈希：用坐标精度“算”随机

> 样本：你给的“值噪声基本命令”“柏林噪声替换命令”“半自动生成补充命令”。
> 它不是普通的 Perlin 公式链，而是利用 Bedrock 浮点坐标精度、`positioned`/`facing`/`align`
> 和实体锚点，把坐标压成伪随机值，再用 `fill` 铺成地形。

## 1. 和 Perlin 的区别

| | 值噪声（value noise） | Perlin |
|---|---|---|
| 每个晶格点 | 一个值 | 一个梯度向量 |
| 插值 | 值之间插值 | 梯度点积后插值 |
| 本样本 | 用坐标精度/实体变换做哈希 | 用 scoreboard 定点算术 |
| 稳定性 | 依赖浮点精度/版本 | 定点整数，稳定 |

所以“值噪声基本命令”更像是 **坐标精度哈希 + 四角插值**，不是把 Perlin 公式抄一遍。

## 2. 核心机制

### 2.1 极端坐标制造精度丢失

命令里反复出现：

```text
23388608
-23388608
1048576
4096
1024
65536
16384
32768
40009 / 40277 / 10091 / 40087 / 10343
```

Bedrock 的坐标是浮点数；在很大坐标上做加法/`positioned`，低位精度会丢失，再配合：

```mcfunction
align xyz
align xz
align x
```

就把连续坐标量化成离散格点。不同方向的偏移组合，产生类似哈希的伪随机值。

> 这是版本相关的“精度副作用”，不是正式随机 API；换版本/平台可能变。

### 2.2 四个锚点 = 四个晶格角

样本用：

```text
a / b / c / d   # 四个方向的 point 盔甲架
nxs            # 方向/采样锚点
xp_orb         # 采样点/像素
fishing_hook   # 玩家/起点
```

四条替换命令分别对应 a/b/c/d 四个角，再用：

```mcfunction
positioned ^^^4000
facing 0 0 0
positioned ^^1000^1000
rotated ~180~
run tp @s ^^1000^1000
```

把角点值插值/搬到采样点。

### 2.3 一个最小结构

```mcfunction
# 1. 载入 point 结构（锚点）
structure load point ~~1~

# 2. 把 point 实体对齐到起点（极端坐标做精度折叠）
execute ... run tp @e[tag=point] ~ 0 ~

# 3. 由 point 生成/变换 xp_orb 采样点
execute as @e[tag=point] at @s ... run summon xp_orb ~ 0 ~ ~ 90

# 4. 采样点落成地形
execute at @e[type=xp_orb] run fill ~ -59 ~ ~ ~-52 ~ grass replace air

# 5. 清理临时实体
execute as @e unless entity @s[name=!n,type=!xp_orb,tag=!point,type=!fishing_hook] run kill @s
```

实际命令很长，但骨架就是：**锚点 → 精度折叠 → 采样点 → fill → 清理**。

## 3. 四个方向/半自动版本

- `a/b/c/d`：四个角的采样分支。
- `n` / `t`：半自动版本的“扫描锚点/时间锚点”，通过 `tp @s ~~~~<y>` 逐行推进。
- `nxs`：方向锚点，用嵌套 `rotated as`/`positioned` 把四角展开。
- `point`：最终落点盔甲架，`fill` 前用它定位。

半自动版本把“手动摆四个角”变成：

```text
n 锚点扫一行 → t 抬高 → 再扫一行
```

但仍然是精度哈希，不是 scoreboard Perlin。

## 4. 关键限制

1. **版本相关**：浮点精度、`positioned` 行为、`align` 取整在版本间可能变。
2. **世界边界**：极端坐标可能超出世界/服务器边界，网易可能 clamp/拒绝。
3. **实体成本**：每个采样点一个 `xp_orb`，四个分支 × 网格，实体数很容易超限。
4. **fill 成本**：每个 orb 一次 `fill`，范围大时很贵；要限制网格和高度。
5. **清理**：不清理 `xp_orb`/临时盔甲架会累积。
6. **不能当逻辑数据**：这是视觉/地形生成，不要用 orb 位置当服务端状态。
7. **命令长度**：单条 `execute` 嵌套很多，接近 32,500 字符上限，最好拆成多个方块。

## 5. 怎么学/怎么复用

不要直接抄 4 条超长命令；先拆成：

```text
A. 锚点/结构载入
B. 一个方向（a）的精度折叠
C. 采样点生成
D. fill 落块
E. 清理
```

先用 **一个方向、4×4 采样**跑通，确认：

- orb 是否出现在预期格点
- `fill` 是否只落在目标区域
- 坐标是否被服务器 clamp
- 清理是否干净

再扩到四方向/16×16。

## 6. 更稳定的替代

如果目标只是“可复现的地形”，优先：

- **scoreboard 定点 Perlin/fBm**（稳定、可调、无浮点依赖）
- 或 **预计算高度表**（最稳，但不是算法）

精度哈希适合做**视觉噪声/艺术效果**，不适合做需要跨版本一致的关键系统。

## 7. 一句话

这套命令的本质是：

> **用大坐标的浮点精度丢失 + align 量化 + 四角实体变换，做一个坐标哈希，再把哈希值落成地形。**

学它要学“为什么精度会变成噪声”，而不是背那四条长命令。

# 系统化归类（从 17 条样本抽象）

## A. 按功能分层

样本编号有重复，不要按编号背；按功能分 7 层：

| 层 | 作用 | 样本对应 |
|---|---|---|
| L0 初始化 | 载入 `point` 结构、准备锚点 | (1) |
| L1 起点/坐标折叠 | 把玩家/鱼钩/主世界坐标折叠到哈希空间 | (2), (11)(12)(13)(14) 前半 |
| L2 四角锚点 | `a/b/c/d` 四方向、`nxs` 方向 | (3), (11)-(17) |
| L3 采样点 | 生成 `xp_orb`，每个 orb 是一个像素/采样 | (4), (11)-(17) |
| L4 插值/搬运 | 四角值映射到采样点 | (5)-(8), (11)-(14) 后半 |
| L5 落块 | `fill ... grass replace air` 形成地形 | (9), (15) |
| L6 清理 | 删除临时实体 | (10) |
| L7 半自动扫描 | `n/t` 锚点逐行推进 | 补充 (11)-(17) |

## B. 形式化模型

把坐标写成 `p = (x,z)`：

```text
q   = precision_fold(p)          # 大坐标 + positioned 造成低位丢失
c   = align_xz(q)                # 量化到格点
v00,v10,v01,v11 = hash(c)        # 四个角（a/b/c/d）
h   = bilinear(v00,v10,v01,v11)  # 值噪声插值
```

与 Perlin 的差别：

- **值噪声**：每个晶格点一个值，插值。
- **Perlin**：每个晶格点一个梯度，点积分后插值。
- 本样本的 `hash` 不是数学哈希，而是 **浮点精度 + `align` 量化**。

## C. 算子（operator）表

| 算子 | 在样本里的作用 | 注意 |
|---|---|---|
| `structure load point` | 载入锚点结构 | 结构里通常带 armor_stand |
| `positioned as <entity>` | 把执行位置设到实体 | 坐标会带实体精度 |
| `positioned ~-1 0~-1` | 半格偏移/去中心 | 让采样避开整数格 |
| `positioned ~23388608~~23388608` | 大坐标折叠 | 低位精度丢失 |
| `positioned ~-23388608~~-23388608` | 反向折叠 | 产生另一组低位 |
| `facing <大向量>` | 归一化方向 | 大向量也参与精度 |
| `positioned ^^^-1048576` | 沿视线反向推 | 2^20 量级 |
| `positioned 0.5 0 0.5` | 半格 | 与 `align` 配合 |
| `align xz` / `align xyz` | 量化到格点 | 噪声的“晶格”来源 |
| `rotated ~45~` / `~180~` | 旋转四角 | 让插值方向转 90° |
| `tp @s ...` | 搬运采样点 | 不产生方块，只改位置 |
| `fill ... grass replace air` | 落成地表 | `replace air` 避免覆盖已有方块 |
| `kill @e ...` | 生命周期 | 必须清理临时 orb |

## D. 实体角色表

| 实体/标签 | 角色 | 生命周期 |
|---|---|---|
| `fishing_hook` | 玩家/起点输入 | 每条命令临时使用 |
| `point` | 四角锚点容器 | 结构载入，结束清理 |
| `a/b/c/d` | 四个晶格角 | 四方向各一个 |
| `nxs` | 方向锚点 | 控制旋转/插值方向 |
| `xp_orb` | 采样点/像素 | 每个采样一个，必须杀 |
| `n` | 半自动扫描锚点 | 扫描期间存在 |
| `t` | 行/时间锚点 | 逐行推进 |
| `armor_stand` | 锚点载体 | 不能当逻辑存储 |

## E. 模式目录

### E1 精度折叠（hash kernel）

```text
p → +大坐标 → +小偏移 → facing → align → 取回
```

目的不是“去远处”，而是让低位数丢失，得到不可预测但可复现的偏移。

### E2 四角值噪声

```text
a = 角(0,0)
b = 角(1,0)
c = 角(0,1)
d = 角(1,1)
V  = bilinear(a,b,c,d)
```

样本用四条几乎相同的长命令分别处理 a/b/c/d，只是 `facing`/`positioned` 的正负号不同。

### E3 采样点/像素

`xp_orb` 是“可被 `at @e[type=xp_orb]` 选中并 `fill` 的位置”。  
orb 不存储高度，只是把坐标带到 `fill` 命令。

### E4 扫描

`n` 负责一行，`t` 负责换行/抬高：

```text
n 扫完一行 → t 增加固定 y → n 回起点 → 下一行
```

样本里的 `~11.6015625`、`~23.90625` 就是扫描步长，不是随机数。

### E5 清理

```mcfunction
execute as @e unless entity @s[name=!n,type=!xp_orb,tag=!point,type=!fishing_hook] run kill @s
```

意图是保留白名单，杀掉其它临时实体；实际选择器要按项目重写，别直接照抄。

## F. 通用模板（抽象版）

```mcfunction
# L0
structure load point ~~1~

# L1-L2：建立起点/四角
execute as @e[type=fishing_hook] at @s run tp @e[tag=point] ~ 0 ~
execute as @e[tag=point] at @s run tp @s ~~~~ -45

# L3-L4：每个方向生成采样点
execute as @e[tag=point,name=a] at @s run summon xp_orb ~ 0 ~ ~ 90
# b/c/d 同理，只改方向

# L5：落块
execute at @e[type=xp_orb] run fill ~ -59 ~ ~ ~-52 ~ minecraft:grass replace air

# L6：清理
execute as @e unless entity @s[name=!n,type=!xp_orb,tag=!point,type=!fishing_hook] run kill @s
```

> 这是结构模板，不是可直接运行的成品；超长 `execute` 要拆。

## G. 复杂度

- 采样点数 `N = 网格宽 × 网格高`。
- 每个采样点 1 个 `xp_orb` + 1 次 `fill`。
- 四方向 = 4 组锚点/命令，但共享采样网格。
- 成本 ≈ `N × (orb + fill + 命令长度)`；`fill` 高度越大越贵。
- 实体上限、区块加载、命令长度是三个硬约束。

## H. 风险矩阵

| 风险 | 影响 | 处理 |
|---|---|---|
| 浮点精度版本差异 | 图案变化/失效 | 固定版本；先小网格测试 |
| 世界边界 clamp | 坐标被截断 | 不要用超出边界的极端值 |
| 实体上限 | orb/锚点丢失 | 限制 N；分批/清理 |
| `fill` 过大 | 卡顿/超时 | 限制高度/范围 |
| 命令过长 | 解析失败 | 拆成多个方块 |
| 临时实体残留 | 卡顿/误选 | 白名单清理 |
| 旧语法 | 版本不兼容 | 统一 `execute as/at/positioned ... run` |

## I. 学习路径

1. **只跑 L0-L2**：确认 point/a-d 位置。
2. **一个方向 4×4**：确认 orb 位置与 `fill` 区域。
3. **四方向 4×4**：确认 a/b/c/d 插值差异。
4. **16×16**：测实体/命令/性能。
5. **半自动 n/t**：确认步长和换行。
6. **清理/重跑**：确认无残留。
7. **记录版本/坐标/网格**：这是精度技术，必须可复现。

## J. 一句话总结

> **值噪声样本 = 精度折叠做哈希 + 四角实体做晶格 + orb 做采样 + fill 做落块；  
> 学的是“坐标如何变成噪声”，不是背 17 条超长命令。**
