# 命令计算基础：把指令当程序，而不是配方

> 目标：先建立**执行模型、内存模型、控制流、数据结构、复杂度**，再写命令。  
> 只会套例子时，遇到新需求就会退化成“堆 `execute`”。

## 1. 执行模型

- 一个命令方块 = 图里的一个**节点**；`chain` = 顺序边；`conditional` = 条件边；`repeat` = 每个 tick 的循环节点。
- `execute` = **执行上下文变换 + 分支**：
  - `as` 改变执行者；
  - `at` 改变位置/维度；
  - `positioned` / `rotated` / `anchored` 改变坐标系；
  - `if` / `unless` 是门；
  - `run` 后面是叶子动作。
- `execute as @e[...] run ...` 会为每个匹配实体各执行一次：**一个节点，N 个分支**。这就是 N 叉树/执行分叉的基础。
- 同一 tick 内没有真正的函数调用栈；要跨 tick 保留“调用者/返回点”，必须显式存计分板/标签。

## 2. 先选计算模型

| 需求形状 | 模型 | 命令侧实现 |
|---|---|---|
| 有明确阶段、可暂停/重置 | 有限状态机 | `fb_state` + `repeat` 推进 |
| 多个输入汇成一个结果 | 数据流/事务 | 输入链 → 校验 → 结算 → 清理 |
| 顺序处理、先进先出 | 队列/环形缓冲 | `fb_head`/`fb_tail` + `fb_q0..N` |
| 后进先出 | 栈 | `fb_sp` + `fb_s0..N` |
| 层级/父子/分叉 | 树 | `fb_parent`/`fb_child` 或 N 叉执行树 |
| 路径/连通/传播 | 图 | 邻接位集/距离表 + BFS 队列 |
| 大量空间点/几何 | N 叉树 + 数学表 | 嵌套 `execute positioned/rotated` + 预计算偏移 |
| 定时/延迟/并行 | 调度器 | 计分板倒计时 + 事件队列 |

## 3. 内存模型

基岩版命令的“内存”只有：

- **计分板**：整数标量；假玩家 `fb_*` 做全局变量。
- **tag**：布尔集合；适合状态标记/分类。
- **实体/方块**：可作为空间索引或持久标记（有成本）。
- **命令方块本身**：只读结构，不是可写 RAM。

常见结构：

```text
数组：fb_a0, fb_a1, ... fb_aN
栈：  fb_sp 指针 + fb_s0..N
队列：fb_head/fb_tail + fb_q0..N（取模回绕）
链表：fb_node0_next, fb_node1_next, ...（用分数存索引）
树：  fb_node0_parent, fb_node0_child0..N（索引编码）
位集：一个整数存 31 个布尔（第 i 位 = 2^i）
```

约定：

- 变量名用 `fb_` 前缀；不要用 `#`（网易会报错）。
- 每个数组显式初始化；不要依赖默认 0 的隐含语义。
- 每个循环/事务结束清理临时 tag；否则下一 tick 重复结算。

## 4. 控制流

- **顺序**：chain 方块。
- **条件**：`execute if/unless`；条件方块只检查前驱成功次数，不要用它做复杂布尔表达式。
- **循环**：`repeat` + 显式计数器；不要依赖环状 chain 在同一 tick 内迭代。
- **分支**：并排多条 chain，或用 `execute if ... run ...` 多个叶子；不要把所有分支硬串进一条条件链。
- **中断**：显式 `fb_abort` 状态/门；不要靠“条件失败”隐式中断整条延迟链。
- **调度**：`fb_timer` 每 tick 递减；到 0 触发事件并从队列取下一个。

## 5. 算法与复杂度

| 算法 | 命令侧 | 成本 |
|---|---|---|
| 线性扫描 | `execute as @e[...]` | O(实体数) |
| 计数 | `scoreboard players add` | O(匹配数) |
| 选择 | `c=1` + 排序/最近 | O(匹配数) |
| 排序 | 冒泡/选择排序（分数数组） | O(N²)，N 必须小 |
| 二分 | 有序数组 + 两端指针 | O(log N)，需要静态表 |
| BFS/DFS | 队列/栈 + visited 位集 | O(节点+边) |
| 动态规划 | 小数组滚动 | O(状态数×转移) |
| N 叉遍历 | 嵌套 execute / 预计算偏移 | O(分支数) |

**命令成本不是只看方块数**：

- 每个 `execute as @e[...]` 会按匹配数分叉；`@e` 太宽会爆炸。
- 一条命令最多 32,500 字符；嵌套 `execute` 过长要拆。
- 一个 tick 的叶子动作总量 = 分支数 × 每分支命令数；按 20 Hz 估算。
- 区块未加载时实体/方块选择器结果会变；关键机关用 `tickingarea`。

## 6. 设计不变量

每个系统至少写 4 条：

1. **状态封闭**：状态只能是枚举内值；越界要钳制。
2. **幂等**：重复触发不会重复扣钱/发奖/召唤。
3. **可重置**：清分数、tag、临时实体、UI。
4. **可观测**：关键状态能在 sidebar/actionbar/输出里看到。
5. **有界**：循环/递归/队列/实体数有上限。

## 7. 从需求到命令的顺序

```text
行为契约
→ 选择计算模型（状态机/数据流/队列/树/图）
→ 设计内存布局（分数/tag/数组）
→ 写数学（范围/取模/钳制/坐标）
→ 写控制流（顺序/分支/循环）
→ 写叶子动作（UI/伤害/生成/方块）
→ 写清理/重置
→ 估算复杂度与命令数
→ 测试边界/多人/重载/重置
```
