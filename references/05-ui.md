## 27. 四通道

| 通道          | 位置          | 特点                 | 每刻能用几个   |
| ----------- | ----------- | ------------------ | -------- |
| `title`     | 屏幕中央**大字**  | 停留约 2 秒，适合事件播报     | 同刻只能一个生效 |
| `subtitle`  | 中央小字（在大字下方） | 需要配 `title` 才有位置   | 同上       |
| `actionbar` | 快捷栏**上方**   | 不占中央视野，**HUD 主战场** | 1 个      |
| `tellraw`   | 聊天栏         | 可多行、可滚动，会刷屏        | 不限       |

```
titleraw @s actionbar {"rawtext":[...]}     ← 常驻 HUD
titleraw @s title     {"rawtext":[...]}     ← 大事件
titleraw @s subtitle  {"rawtext":[...]}     ← 大事件副标题
tellraw   @s          {"rawtext":[...]}     ← 详细面板 / 结算
```

❗ `title` / `subtitle` / `actionbar` **同一刻只能有一个生效**。  
同刻发两条，后一条覆盖前一条。

❗ `title` 不支持纯文本语法混用：`title @s title 纯文本` 可以，但不支持 `§` 之外的 JSON。  
要用 JSON 一律走 `titleraw`。

### 通道选择决策

| 要显示什么         | 用哪个                  |
| ------------- | -------------------- |
| 血量、能量、连招数（常驻） | `actionbar`          |
| 菜单            | `actionbar`（多行）      |
| 升级、暴击、击杀（一次性） | `title` + `subtitle` |
| 详细数值面板、结算清单   | `tellraw`            |
| 受伤飘字          | `actionbar` 里嵌条件片段   |

## 28. JSON 规格与 `%%N`

### 28.1 顶层

```json
{"rawtext":[ <片段>, <片段>, ... ]}
```

❗ `rawtext` 是**唯一**顶层键。`{"text":"..."}` 直接当顶层会静默失败。

### 28.2 五种片段

| 片段   | 写法                                            | 输出                 |
| ---- | --------------------------------------------- | ------------------ |
| 文本   | `{"text":"§a你好"}`                             | 原样文本，`§` 上色        |
| 计分   | `{"score":{"objective":"level","name":"@s"}}` | 该目标在该玩家上的分数        |
| 选择器  | `{"selector":"@s[scores={hp=1..}]"}`          | 命中输出玩家名，**不命中输出空** |
| 翻译拼接 | `{"translate":"%%N","with":{...}}`            | 拼接片段               |
| 键位   | `{"keybind":"key.jump"}`                      | 极少用                |

### 28.3 `%%N` 是**参数索引**，从 1 起

```json
{"rawtext":[{"translate":"Hello %%2 and %%1","with":{"rawtext":["Steve","Alex"]}}]}
→ "Hello Alex and Steve"
```

`%%2` 取第 2 个参数，`%%1` 取第 1 个，可重复引用、可乱序。

❗ **`%%N` 不是"参数个数"**。这是最容易写错的一条。

### 28.4 条件渲染的全部机制

`with` 里若含选择器且选择器**未命中**，整个 `translate` 组件解析失败 → **整段输出空**。

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={energy=100}]"},     ← 第 1 个：闸门，不渲染
  {"text":" §e§l满"}                          ← 第 2 个：真正输出
]}}
```

这一条机制撑起了整个 UI 体系：**一行 JSON 里塞几十个"如果…就显示…"**。

### 28.5 前缀 + 数值必须嵌套

`%%N` 只输出**一个**参数。想输出"§c + 数值"，不能写成 `%%3` 配三个参数：

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={hp_hurta=1..}]"},
  {"translate":"§c%%1","with":{"rawtext":[{"score":{"objective":"hp_hurt","name":"@s"}}]}}
]}}
```

内层 `{"translate":"§c%%1"}` 是**格式串**：静态 `§c` + 第 1 个参数（分数）。

### 28.6 换行

❗ **必须写 `\n` 两个字符**（反斜杠 + n）。源码里写成真换行 → JSON 非法 → 整条静默失败。

Python 生成时用 `cmd.replace("\n", "\\n")` 统一转义。

### 28.7 百分号陷阱

❗ `%%2` 若经过 Python `%` 格式化会变成 `%2`，条件拼接立刻失效。  
**拼 JSON 只用字符串 `+`，永远不用 `%` 或 f-string 去套 `%%N`。**

## 29. 条件拼接（一个 `%%N` 顶十个方块）

### 29.1 开关型

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={菜单=1}]"},
  {"text":"§d▶ §f"}
]}}
```

菜单选中就出现 `§d▶ §f`，没选中就什么都不输出。

### 29.2 二选一型

```json
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={gun=0}]"},{"text":" §7<§r 未装备 §7>"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={gun=1..}]"},{"text":"§7 <§r 已装备§7 >"}]}}
```

两条并列，一条命中一条空。

### 29.3 多选一型（N 个独立组件并列）

❗ **先纠正一个常见误解**：`with` 里放多个选择器，&#x662F;**"与"**&#x4E0D;&#x662F;**"或"**。  
只要有一个选择器未命中，整个 `translate` 就解析失败。  
所以"8 个闸门 + 1 个 `%%9`"这种写法**不是 8 选 1**，而是"8 个条件全满足"。

真正的多选一，是**在 `rawtext` 顶层并列 N 个独立组件**，每个只管自己那一档：

```json
{"rawtext":[
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=1}]"},{"text":"｜ > 起源之地 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=2}]"},{"text":"｜ > 卡莫纳藏身处 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=3}]"},{"text":"｜ > 乔木镇草原 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=4}]"},{"text":"｜ > 苏梅克贸易区 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=5}]"},{"text":"｜ > 卡莫纳电视台 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=6}]"},{"text":"｜ > 私人藏身处 ｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=7}]"},{"text":"｜ > 请输入文本 ｜"}]}}
]}
```

`地区=3` 时，只有第 3 个组件命中 → 只输出第 3 段文字。其余组件各自失败、各自空输出，  
互不影响。**这就是"用并列实现 OR"**。

代价是文本长度翻倍（每条组件都要写一遍 `%%2` 外壳），  
但**语义清晰、绝不出错**，这是推荐写法。

### 29.3.1 用阈值压缩写法

如果各档文本是"同一句话 + 不同后缀"，可以省掉重复：

```json
{"rawtext":[
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=1..}]"},{"text":"§f地区：起源之地"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=2..}]"},{"text":"§f地区：卡莫纳藏身处"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={地区=3..}]"},{"text":"§f地区：乔木镇草原"}]}}
]}
```

❗ 用 `N..` 而不是 `=N` 时，**后面的组件必须写在前面**（或者用 `=N`）。  
否则 `地区=5` 会同时命中 `1..` `2..` `3..` 三段，输出三行。

**结论**：要么用 `=N` 精确匹配（可以任意顺序），要么用 `N..` 并倒序书写。  
混用必错。

### 29.4 多条件与（同一条命令里）

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={burst_cd=1..}]"},
  {"text":"  §7冷却 §f"}
]}}
```

选择器里可以写多个 `scores` 条件，全部满足才命中。

## 30. 格式串混排

`translate` 的字符串里可以**同时写静态字符和 `%%k`**：

```json
{"translate":"\n§o ▏▏▏%%1▏§2%%2▏▏§2%%3▏▏▏§2%%4▏▏▏▏§2%%5▏▏▏▏▏▏▏§2%%6▏▏▏▏▏▏▏▏▏","with":{...}}
```

`▏` 的个数就是格子宽度，`%%k` 取第 k 个参数。用于"**非等宽条形图**"。

```json
{"translate":"\n  §2§o ▏▏▏§a│ ─ §b─ -{§aL§qA §eS§gM§6P§b}-─ §a─ │‖§2\n§o  ▏▏▏%%1▏§2%%2▏▏..."}
```

这一条里混了：换行、缩进空格、`§o` 斜体、块字符 `▏│─‖`、六个材质色、  
以及 8 个动态格子。**一条命令画出一整块面板。**

`%%s` 也可用（顺序取参），但和 `%%N` 混写时行为不稳定，**只用 `%%N`**。

### 31.4 顺序：先色后格式

❗ **新的颜色码会清掉所有格式**。所以必须"先色后格式"：

```
§c§l文字§r      ← 对：红色粗体
§l§c文字        ← 错：§c 把 §l 清掉了，只是红色
```

### 31.5 配色套路（从实战文档提炼）

| 用途       | 配色                                  |
| -------- | ----------------------------------- |
| 主标题      | `§l§f` + 主题色做角标（`§d` / `§b` / `§2`） |
| 次要信息     | `§7` 灰                              |
| 强调数值     | `§e` 金 / `§6` 深金                    |
| 危险 / 扣血  | `§c` 红 / `§4` 深红                    |
| 成功 / 加血  | `§a` 绿 / `§2` 深绿                    |
| 未激活 / 禁用 | `§8` 深灰                             |
| 选中态      | `§d` 粉 + `§c§o` 组合                  |

**一条铁律**：一段文字里**不要超过 3 个颜色**，多了就花。

## 32. 块字符与图标（全表）

### 32.1 条状填充（宽度递增）

```
▏ ▎ ▍ ▌ ▋ ▊ ▉ █
```

| 字符  | 视觉宽度 | 用途       |
| --- | ---- | -------- |
| `▏` | 1/8  | 细刻度、非等宽条 |
| `▎` | 2/8  |          |
| `▍` | 3/8  | 血条分段     |
| `▌` | 4/8  | 半格、边框竖线  |
| `▊` | 6/8  | 弹窗边角     |
| `█` | 8/8  | 满格       |

### 32.2 血条专用（藏文符号，等宽且无空隙）

```
ࡇ   （U+0887）—— 实心，20 格条的主力
ࡆ   （U+0886）—— 略窄，Boss 血条用
```

`ࡇ` 在基岩版字体里**严格等宽**，20 个连起来就是一条无缝的条。  
`▏▌█` 这类方块字符有亚像素间隙，连起来会看到竖纹。

### 32.3 水平线与框线

```
─  │  ┃  ╟  ╢  ╔  ╗  ╚  ╝  ├  ┤  ┬  ┴
▔  ▁  ▃  ▆  ░  ▒  ▓
```

- `▔` 做上分隔线（`§u▔▔▔▔...` 20 个）
- `─` 做细横线，`━` 做粗横线
- `╟╢` 做标题两侧的括号（`§d◁╢ 标题 §d╟▷`）

### 32.4 箭头与三角

```
◁  ▷  ◀  ▶  ◢  ◣  ◤  ◥  ➤  ▶
```

- `◁ ▷` 标题两侧（空心三角，轻）
- `▶` 菜单选中项（实心三角，重）
- `◢◣◤◥` 弹窗四角

### 32.5 装饰符号

```
◇  ◆  ◎  ●  ☉  ∬  ❖  ✦  ⚔  ⚡  ‖  །  ▰  ▱  ◉
```

实战用法：

| 符号  | 出现在哪                           |
| --- | ------------------------------ |
| `∬` | 状态栏装饰头（`∬§b∬ §f- Condition`）   |
| `◉` | 弹窗中心图标（`§c☉§7`）                |
| `།` | 标题内部分隔（`§g◁§7།§f 交易市场 §7།§g▷`） |
| `▰` | 渐变装饰条（`§8▰▰§7▰▰▰§f▰▰▰▰▰§e▰`）   |
| `#` | 列表项前缀（`§g# §rinformation`）     |
| `*` | 提示符（`§e* §r`）                  |
| `>` | 层级箭头（`>>> information`）        |

### 32.6 装饰头的三种写法

```
§d◁╢ §f鱼竿枪 §d╟▷ §8遥遥领先.
§2◁╢ §f组队系统 §2╟▷ §8Team-up system.
∬§b∬ §f- Condition >勇者之城 低头传送 ｜交易市场｜
```

公式：`主题色 + ◁╢ + §f + 中文名 + 主题色 + ╟▷ + §8 + 英文副标题`

## 33. 标题栏与分隔线

### 33.1 三层标题结构

```json
{"rawtext":[
  {"text":"§p▏§7 * §dGUN §7*§r 菜单menu §r>>> information§r\n"},
  {"text":"§7---------------------------------------------------\n"},
  {"text":" §r在规定的时间内丢出物品装卸 §e* §rThrow it out in time"}
]}
```

```
§p▏§7 * §dGUN §7*§r 菜单menu §r>>> information        ← 第一行：装饰 + 标题 + 状态
§7---------------------------------------------------  ← 第二行：分隔线
 在规定的时间内丢出物品装卸 §e* §rThrow it out in time  ← 第三行：说明
```

三行各司其职：

| 行 | 作用                                 | 配色                |
| - | ---------------------------------- | ----------------- |
| 1 | 装饰符号 + 模块名 + 状态（`>>> information`） | 主题色 + `§7` + `§f` |
| 2 | 分隔线                                | `§7`              |
| 3 | 一句话说明（中英对照）                        | `§r` + `§e` 强调    |

### 33.2 分隔线的三种规格

```
§7---------------------------------------------------
§u▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
§7--------------------------------------------------------------
```

| 规格 | 长度       | 配什么  |
| -- | -------- | ---- |
| 短  | `-` × 51 | 小菜单  |
| 中线 | `▔` × 20 | 标题下方 |
| 长  | `-` × 62 | 全屏面板 |

❗ 分隔线长度要**和内容宽度匹配**。内容 20 字配 62 个横线，看着像断了两截。

### 33.3 渐变装饰条

```json
{"rawtext":[{"text":"§r§8▰▰§7▰▰▰§f▰▰▰▰▰§e▰§f▰▰▰▰▰§7▰▰▰§8▰▰\n§2     <§a<§3<§b< m e n u §3>§a>§2>\n§r§8▰▰§7▰▰▰§f▰▰▰▰▰§e▰§f▰▰▰▰▰§7▰▰▰§8▰▰"}]}
```

渲染：

```
▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰          ← 两侧深、中间亮
     < < < m e n u > > >        ← 箭头逐层收拢
▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰
```

**原理**：用 `§8 → §7 → §f → §e → §f → §7 → §8` 的对称色阶模拟发光。  
字母之间**加空格**（`m e n u`）让标题变宽、有呼吸感。

**这是唯一值得用的"渐变"**——因为它是**对称色阶**，不是真渐变，  
看起来像"灯从中间亮起来"，而不是"糊了一片"。

### 34.6 两栏框线布局（实战拆解）

先看一个真实成品：

```json
{"rawtext":[{"text":"§d▁▁▁▁▁▁▁▁▁▁§b◢［§3ＤＥＡＤ†ＢＬＡＤＥ§b］◣§d▁▁▁\n§d│  §7魔能刻印  §d│             §7- 悬棱幻境 -         §d╱\n §d│            §d│﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎╱\n §d╢§b▷ §f返回主城 §b◁§d╟│§b➤ §f查询有关玩家的各类信息\n §d│            §d│\n§d│  §7个人信息  §d│╱▔▔▔▔▔▔▔▔▔▔▔▔▔▔ §3☬\n§d▔▔▔▔▔▔"}]}
```

渲染出来是这样：

```
▁▁▁▁▁▁▁▁▁▁◢［ ＤＥＡＤ†ＢＬＡＤＥ ］◣▁▁▁
│  魔能刻印  │             - 悬棱幻境 -         ╱
 │          │﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎╱
 ╢▷ 返回主城 ◁╟│➤ 查询有关玩家的各类信息
 │          │
│  个人信息  │╱▔▔▔▔▔▔▔▔▔▔▔▔▔▔ ☬
▔▔▔▔▔▔
```

#### 逐行拆解

| 行 | 作用                       | 用的字符                |
| - | ------------------------ | ------------------- |
| 1 | **顶栏**：横线铺底，标题嵌进去        | `▁` + `◢［ ］◣`       |
| 2 | **左栏项** + 右栏副标题          | `│` 中轴 + `- -` 包裹   |
| 3 | 右栏**次级分隔**               | `﹎` 波浪线 + `╱` 斜角    |
| 4 | **主按钮**（有框）+ **次按钮**（无框） | `╢ ╟` + `▷ ◁` + `➤` |
| 5 | 空行留白                     | `│` 保持中轴            |
| 6 | 左栏第二项 + 右栏底边 + 收尾图标      | `╱` + `▔` + `☬`     |
| 7 | **底边**                   | `▔`                 |

#### 五个设计手法

**① 全角字母做大标题**

```
ＤＥＡＤ†ＢＬＡＤＥ
```

全角字符宽度是半角的两倍，天然自带**字距**。  
比 `§lDEAD BLADE` 更稳、更有仪式感，而且**不需要 `§l`**（全角本身就很重）。

|                |                             |
| -------------- | --------------------------- |
| `†` 当分隔符——比 \` | ` `-` `/\` 都更有设计感，且不会和框线混淆。 |

**② 标题"嵌"进横线**

```
▁▁▁▁▁▁▁▁▁▁◢［ 标题 ］◣▁▁▁
```

`◢` 和 `◣` 是**斜切角**，让标题像"从线里长出来"。  
`［ ］` 再加一层括号，形成"线 → 角 → 括号 → 文字"四级收束。



**③ 两栏用 `│` 做中轴**

```
│  魔能刻印  │             内容
```

左边窄（项目列表），右边宽（内容）。中轴用同一个 `│`，  
**所有行都对齐到它**——这是整块界面的骨架。

❗ 中轴位置必须**逐行数准**。错一格整块就歪了。

**④ 斜角收尾**

```
内容 ╱
```

每栏右侧用 `╱` 收尾，制造"切角"的现代感，比直角 `│` 轻。  
配合 `﹎`（波浪线）做次级分隔，比 `-` 软，比空格实。

**⑤ 按钮的视觉重量分层**

| 层级      | 写法              | 视觉重量        |
| ------- | --------------- | ----------- |
| **主按钮** | `╢▷ 返回主城 ◁╟`    | 重（双框 + 双箭头） |
| **次按钮** | `➤ 查询有关玩家的各类信息` | 中（单箭头，无框）   |
| **列表项** | `  魔能刻印`        | 轻（只有缩进）     |

三层重量差靠**符号数量**和**框线有无**实现，不靠颜色。  
颜色只用 `§d`（紫，主色）/ `§7`（灰，次）/ `§f`（白，正文）/ `§3`（青，点缀）。

#### 成本

这一整块界面 = **1 个命令方块**。  
7 行 × 约 40 字符 = 280 字符，远低于命令方块 32767 的上限。

#### 可扩展的骨架模板

```
▁▁▁▁▁▁▁▁▁▁◢［ 主标题 ］◣▁▁▁
│  项目一    │             副标题              ╱
 │          │﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎╱
 ╢▷ 主操作 ◁╟│➤ 次要说明
 │          │
│  项目二    │╱▔▔▔▔▔▔▔▔▔▔▔▔▔▔ 图标
▔▔▔▔▔▔
```

把"项目一/项目二"换成动态片段（`%%2` + 闸门），就是可交互菜单。

### 34.7 视觉层级：iOS 原生感

> 核心不是花哨的毛玻璃和渐变，而是**安全区、大标题、按钮层级**这些细节堆出来的"原生感"。  
> 清楚、克制、顺手，比炫技重要。

命令方块做不出毛玻璃，但**能做出"清楚"**。下面是可直接执行的规则。

#### 34.7.1 安全区：内容不贴边

真机上内容永远不会顶到屏幕边缘。命令方块里对应的是**左右留白**。

```
❌ §f魔能刻印
✅ §d│  §7魔能刻印  §d│
```

- 左右各留 **1–2 个全角宽度**（≈2–4 个半角字符）
- `actionbar` 可用宽度约 40 个半角字符，**内容区只用中间 32 个**
- 上下也要留：第一行前加 `\n`，最后一行后加 `\n`

| 通道          | 左右安全区 | 理由               |
| ----------- | ----- | ---------------- |
| `actionbar` | 2 字符  | 太长会被屏幕边缘裁掉       |
| `subtitle`  | 4 字符  | 居中显示，两侧容易被 HUD 挡 |
| `tellraw`   | 0     | 聊天栏自己会换行         |

#### 34.7.2 大标题：一级信息必须"大"

iOS 的 `Large Title` 是 34pt，正文是 17pt —— **一级是二级的两倍**。

命令方块里"字号"改不了，但能改**视觉宽度**：

| 手段                   | 效果        |
| -------------------- | --------- |
| **全角字母** `ＤＥＡＤ`      | 宽度 ×2     |
| **字母间加空格** `m e n u` | 宽度 ×1.5   |
| **`§l` 粗体**          | 视觉重量 +30% |
| **两侧加装饰** `◢［ ］◣`    | 视觉重量 +50% |

一级标题至少用两种手段叠加：

```
◢［ ＤＥＡＤ†ＢＬＡＤＥ ］◣        ← 全角 + 角 + 括号，三重
```

二级信息（副标题、说明）**只用 `§7` 灰 + 正常字宽**，绝不加粗：

```
- 悬棱幻境 -              ← 灰 + 破折号，安静
```

❗ **一级和二级必须有明显差**。全都加粗 = 全都没有重点。

#### 34.7.3 按钮层级：三种，不要四种

| 层级       | 用途          | 写法         | 颜色              |
| -------- | ----------- | ---------- | --------------- |
| **主操作**  | 这一屏最想让人点的那个 | `╢▷ 文字 ◁╟` | `§b` 青 / `§d` 粉 |
| **次操作**  | 其他可选操作      | `➤ 文字`     | `§f` 白          |
| **危险操作** | 删除、重置、退出    | `✕ 文字`     | `§c` 红          |

规则：

1. **一屏只允许一个主操作**。两个主操作 = 没有主操作
2. 主操作放**第一行**（视线起点）
3. 危险操作放**最后一行**，且和主操作隔开一行
4. 三种层级**用符号区分，不靠颜色**——色弱玩家也能分辨

#### 34.7.4 间距阶层：用 1 / 2 / 4 空格解决一切

不要随手打空格。用固定的三档：

| 阶层    | 空格数 | 用在哪                    |
| ----- | --- | ---------------------- |
| **紧** | 1   | 同一组内的字段之间（`§7等级 §f12`） |
| **中** | 2   | 不同组之间、按钮前后             |
| **松** | 4   | 区块之间、标题与正文之间           |

```
▁▁▁▁▁▁▁▁▁▁◢［ 标题 ］◣▁▁▁
│  项目一    │             副标题              ╱     ← 松（4）
 │          │﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎﹎╱
 ╢▷ 主操作 ◁╟│➤ 次要说明                              ← 中（2）
 │          │
│  项目二    │╱▔▔▔▔▔▔▔▔▔▔▔▔▔▔ 图标
▔▔▔▔▔▔
```

❗ **不要出现 3 个、5 个、7 个空格**。阶层一旦乱，整块就显得"业余"。

#### 34.7.5 克制：明确"不做什么"

| 不做             | 为什么                    |
| -------------- | ---------------------- |
| **渐变**         | 字符世界里做不出真渐变，只是色阶堆叠，看着脏 |
| **毛玻璃 / 半透明**  | 做不出来，别假装               |
| **超过 3 种颜色**   | 超过就花，且失去主色             |
| **超过 2 种装饰符号** | 符号是标点，不是墙纸             |
| **满屏边框**       | 边框是为了**分组**，不是为了填满     |
| **每行都加粗**      | 全加粗 = 无重点              |
| **居中和左对齐混用**   | 选一种，从头到尾               |

**判断标准**：把界面缩小到看不清字，只看色块分布——  
如果是一团乱，就是太花；如果有明显的**块状结构**，就是对的。

#### 34.7.6 一份"原生感"检查清单

出图前逐条过：

1. 左右是否留了安全区？
2. 一级标题和二级信息是否有明显宽度/颜色差？
3. 一屏是否只有一个主操作？
4. 危险操作是否在最下面且隔开？
5. 间距是否只用 1 / 2 / 4？
6. 颜色是否 ≤3 种？
7. 装饰符号是否 ≤2 种？
8. 中轴（`│`）是否逐行对齐？
9. 缩进是否统一（不要有的 1 空格有的 2 空格）？
10. 去掉所有颜色后，结构是否还看得懂？（色弱测试）

**第 10 条是终极标准**：如果去掉颜色就散架，说明你在靠颜色撑结构，那是虚的。

### 34.7.7 全角字符：等宽、稳重、能对齐

#### 三套字符

| 类别       | 字符                          | Unicode     |
| -------- | --------------------------- | ----------- |
| **全角大写** | ＡＢＣＤＥＦＧＨＩＪＫＬＭＮＯＰＱＲＳＴＵＶＷＸＹＺ  | U+FF21–FF3A |
| **全角小写** | ａｂｃｄｅｆｇｈｉｊｋｌｍｎｏｐｑｒｓｔｕｖｗｘｙｚ  | U+FF41–FF5A |
| **全角数字** | ０１２３４５６７８９                  | U+FF10–FF19 |
| **全角标点** | ： ！ ？ ， ． 、 （ ） ［ ］ ｛ ｝ 【 】 | —           |

#### 为什么值得用

**① 严格等宽**。每个全角字符占**两个半角宽度**，在基岩版字体里不会因字形宽度不同而错位。  
这是字符界面里唯一能做出"表格对齐"的手段。

**② 自带字距**。不用手动加空格就有呼吸感：

```
ＤＥＡＤ†ＢＬＡＤＥ        ← 全角，天然有字距
D E A D † B L A D E        ← 半角 + 手动空格，宽度不好控
```

**③ 不需要 `§l`**。全角本身就很"重"，加粗反而糊。

**④ 标点不挤**。中文用全角标点，和汉字同宽：

```
✅ §f提示：请先按初始化
❌ §f提示:请先按初始化        ← 半角冒号，紧贴汉字
```

#### 用法对照

| 用途    | 写法                  | 效果           |
| ----- | ------------------- | ------------ |
| 大标题   | `ＤＥＡＤ†ＢＬＡＤＥ`        | 宽、稳、有仪式感     |
| 章节编号  | `０１` `０２` `０３`      | 两位数不跳宽       |
| 静态数值  | `ＬＶ．０５`             | 和标题同一视觉层级    |
| 菜单项序号 | `０１` `０２` / `①` `②` | 比 `#` `*` 清楚 |
| 中文标点  | `：` `！` `？` `（` `）` | 和汉字同宽        |

#### 对齐技巧：用全角做假表格

```
０１  ＡＴＫ  １２５
０２  ＤＥＦ  ０８７
０３  ＨＰ   ５６０
```

三列都齐——因为全角等宽。换成半角数字就乱了：

```
01  ATK  125
02  DEF  87          ← 位数一变，整列错位
03  HP   560
```

#### 动态数值怎么办

`{"score":{...}}` 输出的是**半角数字**，位数不定，没法靠全角对齐。三个办法：

| 办法         | 做法                    | 适用      |
| ---------- | --------------------- | ------- |
| **放行尾**    | 数值后面不再对齐任何东西          | 最常见     |
| **固定宽度容器** | `§8[§f%%1§8]`，用括号吸收差异 | 中       |
| **补前导空格**  | `§7　§f` 全角空格占位        | 需要严格对齐时 |

#### 行宽预算

全角占两格，**预算按 2 算**：

| 通道          | 可用半角宽 | 全角字符上限 |
| ----------- | ----- | ------ |
| `actionbar` | ≈40   | **20** |
| `subtitle`  | ≈60   | **30** |
| `tellraw`   | 不限    | —      |

❗ 一行超过 20 个全角字符，`actionbar` 就会被屏幕边缘裁掉。

#### 三条混排规则

1. **中文正文用全角标点，指令和英文用半角** —— 别在 `execute` 里混全角
2. **同一行不要混用全角数字和半角数字** —— 一个跳宽整行就歪
3. **全角大写和小写别混** —— `ＤＥＡＤ` 和 `ｄｅａｄ` 宽度一样，但字形差很大，  
   混在一行里像两个字体

#### 小结

**全角用来摆版面，半角用来写内容。**

## 36. 状态标签

```
§7<§r 未装备 §7>      ← 未激活
§7 <§r 已装备§7 >     ← 已激活
```

括号用 `§7` 灰、内容用 `§r` 白，视觉上是"半包围"的标签。

### 36.1 二选一标签（标准写法）

```json
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={gun=0}]"},{"text":" §7<§r 未装备 §7>"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={gun=1..}]"},{"text":"§7 <§r 已装备§7 >"}]}}
```

❗ 两个条件必须**互斥且完备**：`=0` 和 `=1..` 正好覆盖全部整数。

### 36.2 多状态标签

```
state = 0  §8[ 未解锁 ]
state = 1  §e[ 可解锁 ]
state = 2  §a[ 已解锁 ]
state = 3  §6[ 已精通 ]
```

```json
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={state=0}]"},{"text":"§8[ 未解锁 ]"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={state=1}]"},{"text":"§e[ 可解锁 ]"}]}},

{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={state=3}]"},{"text":"§6[ 已精通 ]"}]}}
```

## 37. 血条与条状图

### 37.1 20 格标准条

```
▏ࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇࡇ
```

- 20 个 `ࡇ`，每格代表 5% 血量
- `hp_t` = `hp / 5`，取值 0..20
- 每格判断 `hp_t=N..` 决定颜色

```python
def bar(obj, cells=20, empty="§8", full="§c"):
    out = '{"text":"§8▏"}'
    for i in range(1, cells + 1):
        out += ('{"translate":"%%2","with":{"rawtext":['
                '{"selector":"@s[scores={%s=%d..}]"},'
                '{"text":"%s"}]}},' % (obj, i, full))
    out += '{"text":"%s"}' % ("ࡇ" * 0)   # 占位
    return out
```

❗ 生成 JSON 只能用字符串 `+`，**不能用 `%` 格式化**（会把 `%%2` 吃成 `%2`）。

### 37.2 分段血条（头 / 身 / 腿）

```
█▍▍▍▍▍▍▍▍▍▍▍▍▍▍▍▍▍▍▍   ← 头（█ 满格）
▍█▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌   ← 胸（▍█▌ 中格）
▍▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌▌   ← 腿（▍▌ 窄格）
```

用不同宽度的块字符区分部位，**视觉上像一个人形**。

### 37.3 四段色阶（血量越低越红）

| 血量     | 颜色      |
| ------ | ------- |
| > 75%  | `§a` 绿  |
| 50–75% | `§e` 黄  |
| 25–50% | `§6` 金  |
| < 25%  | `§4` 深红 |

实现时每格判断自己的阈值，而不是判断整体血量。

### 37.4 非等宽条（用 `▏` 数量表示宽度）

```json
{"translate":"\n§o  ▏▏▏%%1▏§2%%2▏▏§2%%3▏▏▏§2%%4▏▏▏▏§2%%5▏▏▏▏▏▏▏§2%%6▏▏▏▏▏▏▏▏▏","with":{...}}
```

`▏` 的个数递增（3、1、2、3、4、7、9），形成**阶梯状渐变**。  
适合做"力量条""蓄力条"这类需要视觉冲击的地方。

### 37.5 格子数换算

```
格数 = 数值 / 满值 × 总格数
```

用计分项预计算，别在 JSON 里算：

```
scoreboard players operation @a energy_t = @a energy
scoreboard players operation @a energy_t /= five sys     ← 100 / 5 = 20 格
```

## 38. 多段色阶与"参数上限"的真相

### 38.1 血条不需要嵌套

很多人以为"一条 `translate` 最多 9 个参数，所以 20 格血条必须嵌套"。  
**这是错的。**

❗ **9 个参数的限制只作用于单个 `translate` 的 `with`。顶层 `rawtext` 没有上限。**

所以 20 格血条就是**顶层并列 20 组**，一组一格：

```json
{"rawtext":[
  {"text":"§8▏"},
  {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=1..}]"},{"text":"§c"}]}},{"text":"ࡇ"},
  {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=2..}]"},{"text":"§c"}]}},{"text":"ࡇ"},
  {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=3..}]"},{"text":"§c"}]}},{"text":"ࡇ"},
  ...
  {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=20..}]"},{"text":"§c"}]}},{"text":"ࡇ"}
]}
```

**每格的机制**：

| `hp_t` | 闸门输出 | 后面跟的字符 | 最终显示             |
| ------ | ---- | ------ | ---------------- |
| ≥ 该格序号 | `§c` | `ࡇ`    | 红色格              |
| < 该格序号 | 空    | `ࡇ`    | 沿用前面的 `§8` → 深灰格 |

关键点：**字符本身永远输出，只有颜色码受闸门控制**。  
所以条不会"缩水"，只会变色。

### 38.2 四段色阶

同一格要按血量区间换颜色，就写 4 组闸门，**区间必须互斥且覆盖完整**：

```json
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=16..}]"},{"text":"§a"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=11..15}]"},{"text":"§e"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=6..10}]"},{"text":"§6"}]}},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=..5}]"},{"text":"§4"}]}},
{"text":"ࡇ"}
```

四组里恰好一组命中，输出一个颜色码，后面跟同一个字符。

| 血量     | 颜色      |
| ------ | ------- |
| > 75%  | `§a` 绿  |
| 50–75% | `§e` 黄  |
| 25–50% | `§6` 金  |
| < 25%  | `§4` 深红 |

### 38.3 颜色与格子位置

**颜色是按"当前血量"给的，不是按"格子位置"给的。**  
所以血量高时 20 格全绿，血量低时 20 格全红——  
不会出现"左边红右边绿"的渐变，除非你**故意**按格子位置分色（见 38.4）。

### 38.4 渐变条（按位置分色）

想让左红右绿，就把颜色判断从"血量"改成"格子序号"：

```json
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=1..}]"},{"text":"§4"}]}},{"text":"ࡇ"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=2..}]"},{"text":"§4"}]}},{"text":"ࡇ"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=3..}]"},{"text":"§6"}]}},{"text":"ࡇ"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=4..}]"},{"text":"§6"}]}},{"text":"ࡇ"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=5..}]"},{"text":"§e"}]}},{"text":"ࡇ"},
{"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={hp_t=6..}]"},{"text":"§a"}]}},{"text":"ࡇ"},
...
```

第 1–2 格永远红、第 3–4 格金、第 5 格黄、第 6 格以后绿。  
满血时整条是"红→金→黄→绿"的彩虹；掉血时从右往左变成深灰。  
**这是最像商业地图血条的做法。**

### 38.5 Boss 血条的实战形态

Boss 血条通常有 20 格 + 4 段色阶 + 居中标题，一条 `subtitle` 装下：

```
BOSS
§4ࡆ§8ࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆ§r
```

结构：

```json
{"rawtext":[
  {"text":"BOSS\n"},
  ...20 组「闸门 + 颜色」+ 20 个 ࡆ...
  {"text":"\n\n\n\n\n\n\n\n\n\n\n\n\n\n"}
]}
```

### 38.6 底部换行填充

```json
{"text":"\n\n\n\n\n\n\n\n\n\n\n\n\n\n"}
```

`subtitle` 的位置由 `title` 决定，末尾补一串 `\n` 把内容**往下推**，  
避免和屏幕中央的大字重叠。

### 38.7 什么时候真的需要嵌套

只有一种情况：**要把一段可变的文字塞进"某格的位置"**，而那段文字自己又要条件拼接。  
这时才用嵌套 `translate`（内层有自己的 9 个参数预算）。

血条、菜单、状态标签都**不需要**嵌套——它们全是顶层并列。

## 39. 进度与倒计时动画

### 39.1 用阈值阶梯做"逐帧动画"

**原理**：把 `计算` 分数当帧号，每帧一个独立组件，只有当前帧命中。

```json
{"rawtext":[
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=..20}]"},{"text":"§r§f >>> ｜ Re in ｜ <<< §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=21..40}]"},{"text":"§r§f §3>§f>§f> ｜ Region infor ｜ <<§3<§f §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=41..60}]"},{"text":"§r§f §3>§b>§f> ｜ Regional information ｜ <§b<§3<§f §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=61..80}]"},{"text":"§r§f §3>§b>§e> ｜ Regional information ｜ <§b<§3<§f §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=81..100}]"},{"text":"§r§f >> §e｜ Regional information ｜§f << §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=101..120}]"},{"text":"§r§f > ｜ §eRegional information§f ｜ < §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=121..140}]"},{"text":"§r§f  ｜ Regional information ｜  §｜"}]}},
 {"translate":"%%2","with":{"rawtext":[{"selector":"@s[scores={计算=141..}]"},{"text":"§r§f｜ Regional information ｜"}]}}
]}
```

每刻 `scoreboard players add @s 计算 3`，`计算` 从 0 涨到 141，界面逐帧推进：

```
 >>> ｜ Re in ｜ <<<
 §3>§f>§f> ｜ Region infor ｜ <<§3<§f
 §3>§b>§f> ｜ Regional information ｜ <§b<§3<§f
 §3>§b>§e> ｜ Regional information ｜ <§b<§3<§f
 >> §e｜ Regional information ｜§f <<
 > ｜ §eRegional information§f ｜ <
  ｜ Regional information ｜
 ｜ Regional information ｜
```

**箭头逐层点亮 → 括号逐层收拢 → 文字逐渐变亮**，读起来就是"正在接近"。

❗ 区间必须**首尾相接、不重叠、不空洞**：  
`..20` `21..40` `41..60` …… 最后一档用 `141..` 兜底（防溢出）。

❗ 帧文本是**整行替换**，不是追加。所以每段都要写完整的 `§r` 开头，  
否则会继承上一帧的颜色状态。

### 39.1.1 帧间隔

`计算` 每刻 +3，则 20 帧约 7 刻（0.35 秒）。  
要慢一点就 +1（每档 20 刻 = 1 秒），要快就 +5。

| 每刻增量 | 每档时长        | 手感    |
| ---- | ----------- | ----- |
| +1   | 20 刻 = 1.0s | 缓慢、庄重 |
| +3   | 7 刻 ≈ 0.35s | 常规    |
| +5   | 4 刻 = 0.2s  | 急促    |

### 39.2 进度条（治疗 / 装填 / 蓄力）

```
进度 = 当前值 / 目标值 × 格数
```

```
§8▏§cࡆࡆࡆࡆࡆ§8ࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆࡆ
```

5 格已满（红），15 格空（深灰）。

### 39.3 倒计时文本

```
§7治疗中 §f3.2s
```

用嵌套 `%%N`：

```json
{"translate":"%%2","with":{"rawtext":[
  {"selector":"@s[scores={治疗=1..}]"},
  {"translate":"§7治疗中 §f%%1§7s","with":{"rawtext":[{"score":{"objective":"治疗","name":"@s"}}]}}
]}}
```

## 41. 排版规范

### 41.1 缩进

用**空格**缩进，不要用 `\t`（制表符在游戏里宽度不定）。

```
§7\n     §f内容        ← 5 个空格
```

### 41.2 行数控制

| 通道          | 建议行数            |
| ----------- | --------------- |
| `actionbar` | 3–6 行（再多会挡住快捷栏） |
| `subtitle`  | 最多 9 行          |
| `title`     | 1 行             |
| `tellraw`   | 不限              |

### 41.3 留白

```
{"text":"\n§7\n"}      ← 空一行 + 一个灰色字符（保持行高）
```

纯 `\n` 有时会被压缩掉，加一个 `§7` 空格能稳定撑开行高。

### 41.4 中英混排

实战套路：**中文主信息 + 英文副标题（更小更暗）**

```
§f治疗系统 §8Healing System
§f组队系统 §8Team-up system.
```

英文用 `§8`，视觉上退到背景层。

### 41.5 数字对齐

- 数值放行尾
- 或用固定宽度容器 `§8[§f...§8]`
- 或用前导空格补齐（`§7   §f`）

## 42. 刷新策略

### 42.1 各通道的刷新成本

| 通道          | 每刻刷新        | 建议           |
| ----------- | ----------- | ------------ |
| `actionbar` | 会闪，且每秒 20 次 | **每秒 1 次**足够 |
| `title`     | 会不断重启动画     | 只在事件发生时发一次   |
| `tellraw`   | 会刷屏         | 只在事件发生时发一次   |

### 42.2 用定时器闸门

```
# 主循环段 B（每秒）
execute if score #tick sys matches 20..
execute as @a run titleraw @s actionbar {...}
```

- 每刻跑：`#tick += 1`
- 每秒跑：HUD

### 42.3 分频刷新

不同元素用不同频率：

```
matches 20..   HUD 主体（每秒）
matches 4..    血条动画（每 4 刻）
每刻           受伤飘字（必须实时）
```

### 42.4 只在状态变化时刷新

```
execute as @a unless score @s 上次显示 = @s 当前值 run titleraw @s actionbar {...}
execute as @a unless score @s 上次显示 = @s 当前值 run scoreboard players operation @s 上次显示 = @s 当前值
```

数值没变就不重发，省一半开销。

## 43. 实战：一个完整菜单

把前面所有技巧拼起来。目标：3 个菜单项 + 2 个状态标签 + 一条分隔线 + 底部提示。

### 43.1 数据准备

```
scoreboard objectives add 菜单 dummy
scoreboard objectives add 装备 dummy
scoreboard objectives add 护甲 dummy
scoreboard players add @a 菜单 0
scoreboard players add @a 装备 0
scoreboard players add @a 护甲 0
```

### 43.2 菜单命令（整条）

### 43.4 成本对比

| 做法                     | 命令方块数   |
| ---------------------- | ------- |
| 每个状态一个方块，逐条判断          | 约 18 个  |
| **本方案（一条 `titleraw`）** | **1 个** |

这就是 `%%N` 的价值：**一个方块顶一个界面**。

### 43.5 状态更新命令

```
# 菜单上下移动（抬头/低头）
execute as @a[scores={菜单=1..},rxm=-88] run scoreboard players add @s 菜单 1
execute as @a[scores={菜单=1..},rx=88]   run scoreboard players remove @s 菜单 1
# 越界回卷
execute as @a[scores={菜单=4..}] run scoreboard players set @s 菜单 1
execute as @a[scores={菜单=..0}] run scoreboard players set @s 菜单 3
# 抬头关闭
execute as @a[scores={菜单=1..},rxm=88] run scoreboard players set @s 菜单 0
```

❗ **回卷判断必须放在移动之后**，且用 `=..0` 而不是 `=0`（防止负数漏判）。
